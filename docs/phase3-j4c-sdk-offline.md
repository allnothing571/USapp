## 2. 实现及边界

`tools/j4c_tablestore_sdk.py` 懒加载固定版本 SDK；默认运输层拒绝全部 I/O，没有可执行的真实云入口或读取凭据的函数。测试显式注入内存响应池，所有 AccessKey 值均为合成字符串，测试期间禁止 socket 连接、DNS 解析及 create_connection。

- 配置只接受本次测试实例命名、上海、表名 `journal`、规范日志身份及对应实例的精确安全地址；不接受任意 URL、HTTP、附加路径或生产表名。这只是本地命名约束，**不是账号和实际资源归属验证**。
- SDK 使用 `NoRetryPolicy`，运输层每次请求另设 `retries=False`、`redirect=False`；不能只关闭 SDK 的重试而遗漏 urllib3 层。[官方重试说明](https://help.aliyun.com/zh/tablestore/table-store-service/developer-reference/python-error-handling)
- 连接池设置证书校验必需、CA 文件、单连接、连接/读取超时 2/3 秒和池等待 1 秒；这些只是参数及桩断言，未运行真实证书/域名/连接失败实验。socket 超时不是 DNS 或整次操作的墙钟截止。
- 每个外观实例只允许一个活动事务。Start 固定同一日志分区；GetRow/GetRange/PutRow/UpdateRow 均携带事务身份，行键固定日志/表范围，范围读取有数量限制，响应最多 1 MiB。
- 插入采用不存在条件；head 更新要求完整前驱规范载荷相等、行存在，且新序号和事件序号前进。它只验证真实 SDK 如何编码条件，**不是完整的头/操作/轮次索引原子发布适配器**。
- Commit/Abort 分开；尝试结束事务后即移除本地活动身份，丢失 Commit 回执不能自动 Abort 或盲重试，而应另行分类权威状态。SDK 错误正文、密钥、响应头不从外观错误信息中回显；异常仍不能证明远端没有提交。
- 不提供 CreateTable、DeleteTable、DeleteRow、ListTable 等操作；不修改用户云资源。实际云权限仍须独立验证。

另校正 J4b 契约中的措辞：元数据事务内禁止**对象存储及其它外部服务**调用；TableStore 自身事务 RPC 当然要在其事务中执行。这不是禁止云事务内所有网络调用。原模型的对象 I/O 锁断言和行为未改变。

## 3. 预检限制

固定包的 DescribeTable 描述中没有可直接核对的局部事务开启标记，不能从描述成功推断已开启。因此外观的 `preflight` 先验证精确主键、表名、不自动过期、单版本、允许更新、无额外索引、预留 0/0，再 Start/Abort 探测事务能力。**当前只用桩执行这三个请求，没有实际云探测。** 建表仍应在创建时启用局部事务，不能事后自动修复。[官方建表要求](https://help.aliyun.com/zh/tablestore/table-store-service/developer-reference/startlocaltransaction)

仅检查点写入身份具有这个预检所需事务权限，恢复只读身份不应因此获得事务推进权。

## 4. 进程截止与复现

`tools/j4c_sdk_offline.py` 启动专属子进程执行测试，使用 `-I -B`、显式临时 SDK 路径与最小环境变量，不传凭据。创建子进程后设置 20 秒执行截止，另有最多 3 秒退出回收；超时只终止本工具持有句柄的子进程，不搜索其它进程。超时结果始终不是“远端未执行”的证明。

测试还实际执行了一个 0.2 秒截止的合成阻塞子进程，确认超时分支能终止/收割该子进程，并保留 unknown 语义。**这是测试运行器的截止，不是已实现的生产云操作工作进程**；尚无真实网络调用的取消或远端完成时限证明。

在仓库根目录复现（不需要云凭据，不访问云账号）：


该目录删除后需按锁重新准备隔离依赖，不能静默从全局环境替代。运行器产生唯一日志和 `.exit`，不覆盖旧日志。
