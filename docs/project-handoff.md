# USapp 项目交接

更新日期：2026-11-23（北京时间）。本文是接手入口。功能细节和测试证据见各专题文档，当前工作树和目标服务器的版本需要分别核对。

## 1. 产品目标

USapp 是供情侣共同使用的私人双人渐进式网页应用（PWA），优先满足两个人在备考、学习和日常生活中互相鼓励的需求。每天可以给对方发布任务、认可一次完成，也可以随手留下留言、纪念日、照片和共同计划。小房间、花园和个人形象让这些日常积累有可见的呈现。当前优先服务已有的两位用户，数据按共享空间隔离，为未来容纳更多独立双人空间保留结构。

最终交付应同时满足三件事。两个人能在各自手机上长期使用，在断网、重复点击、账号切换和编辑冲突后能理解状态并继续操作。开发者能维护目录、审阅账本、处理有限的异常并追溯记录。应用能从明确版本重建，并能在经过验证的环境里升级、回退和恢复数据。

## 2. 范围和产品原则

| 范围 | 包含什么 |
| --- | --- |
| V1 日常主流程 | 邮箱验证码登录、创建或受邀加入空间、双向任务和完成反馈、余额和流水、现实奖励兑换与履约、留言与反应、纪念日、提醒和网页推送。 |
| V1 双人记录 | 照片回忆、相册、愿望与计划、内容编辑申请和历史、未绑定照片找回、照片与回忆删除及撤销、结构化用户数据导出。 |
| V1 成长和运维 | 阳光装扮目录、购买、衣柜和穿戴，首批五枚任务徽章，独立管理后台，带审计的资产纠错和未履约兑换取消退款，备份、恢复与删除日志。 |
| V2 共享空间 | 小房间、共享家具、双人站位和形象展示、在线状态、布局实时保存与冲突处理、共享花园与浇水日历。当前视觉迭代还覆盖全站暖色手绘外观和可分层装扮素材。 |
| 当前范围之外 | 现金支付或资产变现、公开社交、实时聊天和音视频、地理追踪、公开排行榜。最小 V1 暂缓奖励与纪念日的可选图片、照片文件打包导出和更多徽章。其余后续想法需要先确定产品规则。 |

- **鼓励和陪伴**。任务到期按规则结束，保留温和提示。双方业务权限对等，开发者管理身份独立于情侣关系。
- **两种资产各有含义**。小红花对应对方提供的现实奖励。阳光承担装扮和家具等虚拟消费。家具由购买成员的阳光账户支出，购买权益归当前空间，两位成员均可摆放。资产变动走追加式流水。
- **共享范围由用户控制**。伴侣形象展示和房间在线状态有独立的授权。房间实时协作限于布局，后端按布局版本判定写入，页面保留冲突草稿。用户同意的内容通知与必须送达站内的个人安全通知遵循各自规则。
- **私密感贯穿界面**。首页、登录和「我们」采用原创小屋、窗景和花园插画。操作页使用平整暖纸底、深墨正文、柿橙主动作、苔绿辅助强调。主色为 `#F8F0E2`、`#352C23`、`#A34D2B`、`#4A6746`。主要触控按钮至少 44 像素，并支持清晰键盘焦点和减少动效。「首页」先呈现房间和花园，随后接今日任务。

## 3. 技术框架和关键规则

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 用户端 | [apps/web](../apps/web) | Vue 3、TypeScript、Pinia、Vite，含路由、离线服务工作线程、身份作用域状态以及双人业务页面。 |
| 管理端 | [apps/admin](../apps/admin) | 独立入口和管理会话。本地或受限管理面用于查看运营数据、管理装扮目录和执行已批准的异常处理。 |
| 应用后端 | [services/api](../services/api) | C++17 和 Drogon 模块化单体。公开与管理监听器职责分离。路由、服务和数据库共同约束身份、权限和业务状态。 |
| 契约与数据 | [OpenAPI](../contracts/openapi.yaml)、[迁移](../database/migrations)、[角色初始化](../database/init-roles.sql) | PostgreSQL 保存空间成员、业务、流水和审计。OpenAPI 记录请求、响应和错误。已有迁移保留原校验和，新变化追加迁移。 |
| 邮件、推送与存储 | [services/push-worker](../services/push-worker)、[deploy](../deploy)、[删除日志协议](phase3-deletion-journal.md) | Caddy 提供同源入口。邮件和推送依赖配置，照片使用私有对象存储和受限签名读取，外部删除日志参与恢复判定。 |
| 测试与运维 | [后端测试](../services/api/tests)、[SQL 测试](../database/tests)、[tools](../tools) | 隔离回归、前后端验证、兼容性检查、加密备份、升级和恢复演练。 |

- 登录会话、空间成员资格和资源归属由服务端核验。写请求保留同源及跨站请求伪造防护。退出登录或更换账号时，请求结果和本地敏感状态按身份清理。凭证和运行配置通过既有安全渠道交接。
- 金融与其他幂等写入保留原请求和键以便确认。结果未知时，通过原键重放或重新读取权威状态。管理员资产纠错要求必填原因、二次确认、绝对差额最多 9,999、结果余额非负，并保留追加式审计。兑换异常处理限未履约的取消及原路退回。
- 时间戳以统一时间存储，任务周期、浇水、连续徽章等日历规则使用北京时间。首批徽章为首次完成任务、累计 10/50 次、连续 3/7 天完成任务，从启用后统计，奖励为徽章。
- 照片逻辑删除后停止签发新链接，恢复窗口内可按现有规则撤销。超过期限的清除与从旧备份恢复均依赖删除日志及权限边界。恢复未确认时保持数据库业务服务关闭，真实对象和数据库需联合演练。
- 房间按 4×3 网格布置，模板、撤销重做和冲突合并以版本化草稿为基础。在线广播仅传达变化信号和已授权的在线状态，客户端再读有权限的快照。断开实时连接时可轮询及手动保存。目前实时通知在单个应用进程内分发。花园每位成员每天可浇一次，累计 3/8/14 次进入后续阶段，提供近七天记录及月历。

### 人物与素材

- [AvatarFigure.vue](../apps/web/src/components/AvatarFigure.vue) 和 [avatar-art.ts](../apps/web/src/api/avatar-art.ts) 负责把 [清单](../apps/web/src/assets/avatar-manifest.json) 中的 512×512 透明画布按顺序叠放。槽位为头发、衣服、表情、帽子、手持物、配饰。区分左右时对整组图层做镜像。邀请发起方选站位，接收方获得另一侧，之后通过换位申请交换。
- `character_gender` 记录个人形象选择，入口使用蓝色男性符号和红粉色女性符号。换位保留该选择及全部穿戴。当前两种形象的清单底模引用同一份 `base.v1.webp`。光头模式通过 `hair_hidden` 隐藏发层，恢复时仍可读取原来的发型选择。
- [提取脚本](../scripts/auto_extract_avatars.py) 在本地做白底分离、头部配准和差分提取，写出透明 WebP、同步清单及后端登记迁移。试穿和小房间共用画布，素材贴合由配准保证。商店和衣柜按分类裁切缩略图，裁切样式只作用于卡片。

## 5. 交付与发布标准

1. **明确交付对象**。记录 Git 提交、构建输入、接口契约、迁移清单和校验和。主要路径以最终发布产物验收。结果记录区分代码实现、自动化验证、浏览器验收、双设备验收、真实服务验收及已部署版本。
2. **跑完自动化并保留证据**。用户端、管理端和推送服务按改动范围运行类型检查、全量测试及构建。后端完成 C++ 构建、CTest、数据库迁移、应用接口和权限检查。使用一次性数据库及合成数据，记录失败原因和复测结果。
3. **完成浏览器与双人走查**。用 Chrome 检查 320、390、768、1440 像素。核对横向溢出、底栏安全区、键盘焦点、对比度、减少动效和加载、离线、未确认状态。两位成员独立登录，走完今日任务、奖励兑换、留言、换位、小房间、花园、装扮保存及刷新。加入跨空间隔离、同时写入、重试和站位互换用例。
4. **验证发布和回退**。先在隔离环境用目标系统的迁移基线演练升级、应用回退、重新前进和数据兼容，再确认生产备份、维护窗口与回退办法。前端、后端及数据库的启用顺序写进发布记录。部署后核对版本、健康检查和实际业务。
5. **真实照片与运维单独验收**。验证真实邮件、推送、存储权限、删除日志、数据库和对象联合恢复以及备份密钥与保留策略。恢复演练证明已删除照片不会重新可见，并保留继续封闭的条件。没有对应环境和证据的项目保持待验收。

## 7. 接手后的顺序

1. 在正确工作树执行 `git status --short --branch`，确认冻结标签及未提交范围。当前本地合成预览入口为 [衣柜](http://127.0.0.1:3820/avatar/wardrobe) 和 [第二位成员](http://127.0.0.1:3821/avatar/wardrobe)。临时入口依赖本机预览进程。
2. 前端依赖按锁文件安装后，在 `apps/web` 运行 `pnpm typecheck`、`pnpm test`、`pnpm build`。检查受影响的页面和失败提示。更新原图后安装 `scripts/requirements-avatar-extraction.txt` 的依赖并运行 `python scripts/auto_extract_avatars.py`。可先加 `--preview-only` 检查拼图，再写入实际素材和迁移，最后用 `node tools/avatar-placeholder-assets.mjs` 校验清单。
3. 准备用于当前版本的编译镜像或等效工具链、隔离 PostgreSQL 以及本地假数据。按 [开发环境](local-development.md) 和 [构建验证脚本](../tools/export-verify.ps1) 执行当前 CTest 和部署前检查。服务端环境配置和线上版本由负责人提供或授权核验。
4. 完成设备与真实服务验收后，记录本次发布的提交、镜像和数据库迁移范围，再安排发布。对于照片恢复，先落实可用的独立测试桶和预发，再执行联合恢复演练。
