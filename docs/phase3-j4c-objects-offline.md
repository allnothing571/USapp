## 2. 对象写入与签名

范围固定为 `usapp-j4c-log-<8位小写十六进制>`、上海、指定日志 UUID（Universally Unique Identifier，通用唯一标识符），以及 `journals/<journal>/batches/<64位散列>.json`。不接受外部端点、查询参数、额外路径或任意头。命名约束不证明资源所有权。

写前检查完整规范字节、日志身份、批次自身散列及对象键。使用 V4 请求头签名，签入内容类型、内容 MD5（Message Digest Algorithm 5，消息摘要算法5）以及全部 x-oss-* 头，包括 `x-oss-forbid-overwrite:true`。只发送一次 PUT；200/409 后必须 GET 并核对完整字节，不能以状态码或 ETag 代替验证。传输错误返回 UNKNOWN，不自动重发 PUT；后续独立读取可以发现已经生效的对象。对象链语义仍由发布模型和元数据适配器独立校验。

V4 规则依据[官方请求头签名文档](https://www.alibabacloud.com/help/en/oss/developer-reference/recommend-to-use-signature-version-4)。供应商例子的规范请求摘要及最终签名已匹配；最终签名使用其公开派生密钥。该密钥不能由页面占位 secret 推导，密钥推导另与仓库既有 C++ 向量核对，不宣称全部向量均为供应商已知答案。

**禁止覆盖依赖版本控制从未启用。** [官方 PutObject 文档](https://www.alibabacloud.com/help/en/oss/developer-reference/putobject)说明，目标桶版本控制为 Enabled 或 Suspended 时，该头无效。名称、签名和本地测试不能代替真实桶设置与权限检查。客户端自身没有查询桶配置权限；后续必须由独立设置/验证身份确认，不能仅依靠所有者记忆或默认值。

读取固定完整响应，最多 1 MiB，拒绝压缩编码；不跟随重定向。显式禁用 urllib3 重试、要求证书验证，连接/读取超时分别为 2/3 秒，连接池等待 1 秒。错误不返回签名、原始响应或凭据。

## 3. 完整发布及调用截止

完整编解码测试使用真实固定 SDK 发送二进制事务、读行、分页、插入、条件更新及提交请求，由状态化内存服务端解析并返回合成签名响应。验证 intent、终结、分页索引、回执丢失后的重新读取，以及中间索引写失败时全部元数据回滚、只留下未引用对象。该服务端自己实现事务行为，**不能证明 TableStore 的原子性、隔离或持久性**。

本地服务仅绑定 `127.0.0.1` 随机端口；测试将固定逻辑端点路由至该自建端口，并另行禁止非本次端口连接和外部域名解析。合成证书只通过单个测试连接池信任。真实验证：加密读回、错误主机名及不可信证书拒绝、重定向不跟随、实际 3 秒停滞读取超时且不重发。

仅有读取超时不足以限制持续慢响应。因此另验证工作进程：服务端先接收完整 PUT，再每 0.1 秒发送少量响应，使 3 秒读取超时不触发；调用预算 2 秒后终止并回收该进程，返回结果未知。断言服务端已接收写入、只收一次 PUT、`proven_not_applied=false`、工作进程已回收。

截止使用单调时钟，调用开始时计时并扣除启动耗时；操作系统进程创建本身及调度不能保证硬实时上限。超过预算后另留最多 2 秒回收，回收失败显式返回 `worker_reaped=false`。该包装器当前为注入调用工具；测试覆盖对象 PUT，不是已接线的实际 SDK 事务或在线发布工作进程。启用真实提供者前，必须将完整事务/发布生命周期放入受控进程并处理未知提交及遗留事务，不能把本工具当作所有现有网络调用都已获得截止保护。
