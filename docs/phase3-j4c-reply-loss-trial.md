## 2. 固定 15 阶段

1. 三名调用者分别验证身份。
2. 桶配置/版本、表配置及 Start/Abort 探测，分别有独立预算。
3. 精确两批次基线完整链及索引验证。
4. 初始化回执与保护行，分别只读验证。
5. loss-intent：正常发布新合成 intent；仅在 SDK 完成 CommitTransaction 的成功解析后，在父进程控制的 SQLite 账本记录 sdk_success_observed，再主动向调用者抛出固定异常。
6. recover-intent：新进程只读取，核对三批次及精确 intent 事实。
7. replay-readonly：再一个新进程重放相同操作；传输层禁止对象 PUT 及 PutRow/UpdateRow/CommitTransaction，必须返回原 READY，且阶段审计中写操作尝试数为 0。
8. abort-intent：显式正常终止这条纯合成 intent，发布 aborted。
9. 完整四批次最终回读、初始化回执、保护行分别检查。

此处“丢答复”是**客户端包装层丢弃已经被 SDK 成功解析的答复**，不是断网、供应商未答复或真实丢包。普通 UNKNOWN、超时、未回收、注入标志未落盘都不会进入下一步。即使标志已落盘，若该进程超时或未回收，仍停止。

loss-intent 是唯一预期调用者 UNKNOWN 的阶段，且只有成功标志、子进程已回收、无超时三者同时成立才确认该受控阶段。不能把它推广为“任何未知写入都继续重放”。本地标志不是供应商持久性、可信当前检查点或抗主机篡改证明。

## 3. 原验证与权限边界

ScenarioMetadata 每次读取必须等于固定场景的完整检查点、批次键、操作索引和删除轮次；基线/新 intent/最终 aborted 对应 2/3/4 批次。Publisher._load 和 Metadata.commit 的独立对象完整性及链验证保留，发布器固定一轮，不在 head 竞争后重试。

对象发布者只负责对象上传；检查点验证用 writer 自己的对象读取凭据；恢复使用 reader 凭据。恢复侧 SDK 传输与外层审计双重拒绝所有数据写入及事务提交；允许 Start/Abort，只做读事务。源表的生命周期、版本等在独立前置阶段核对，不伪装成原子配置快照。

默认不读取或检查所传凭据、旧证据、依赖或状态路径。真实运行同时要求 --run、--ack-synthetic-extension-and-reply-discard、精确 --scenario-sha、保护凭据文件、固定临时依赖、正向及权限两份旧证据、全新状态目录。开关和文件都不替代用户实际授权。

不支持续跑、更换场景、自动清理或通过命令行切换到 C11b。任何失败都保留证据、候选对象、原目录与本次目录；不自动标记 aborted，不推断未应用，不发送第二次写入。

## 4. 截止、配额与本地恢复

每个工作进程仍固定 5 秒，离线测试进程仍 20 秒，没有扩大。父进程只处理自有子进程。真实延迟可能超过截止，此时结果未知且停止；本地测试通过不保证真实服务一定能在 5 秒内完成。

使用原 Trial 限额；API（Application Programming Interface，应用程序编程接口）审计与网络请求预扣在**同一 SQLite 事务**中提交后才允许网络发送，减少重复同步，不删记录或延后预扣。记录固定 API 类别，不存 URL、请求体、密钥、返回正文或事务 ID。响应预留/结算沿用旧规则。

只结转两份已知计数：正向 88 请求、负向累计 91 请求，合计已知 179；3 次对象 PUT 尝试（其中一次被拒绝）、upload 3439、wire 35949、receive 65956。负向 91 已包含先前 51/30，不能再加一次。早期身份/桶预检等不在这两份账本里，因此不是账号总请求或总费用。旧合成操作占用本地操作登记，新操作另登记；本地两小时窗口不会让永久密钥自动过期。5 元仍是人工预算。

新增本地 reply_loss_marker 与分阶段 reply_loss_api 表。只有 SDK 成功返回后才写 marker；若写标志失败或进程在此处结束，不算成功注入。候选对象键继续在 PUT 前记录。

测试发现：子进程在 SQLite 事务中被回收，可留下 hot rollback journal，使只读连接导出时报 attempt to write a readonly database。新入口仅在确认子进程已回收后，以 mode=rw 打开其**已有**账本，让 SQLite 恢复未提交的本地事务，并核对 manifest/nonce/parent PID；不执行清空、退款或预算重置 SQL。已提交的发送前预扣不会因此丢失，未提交的 marker 不会伪装成成功。这个恢复不涉及云端回滚，也不能证明远端租约消失。单测用崩溃进程验证已提交计数保留、未提交修改回滚。

## 5. 证据与完整性限制

全新目录保存 trial-evidence.json、配额/标记账本，含固定场景、旧已知消耗、每阶段结果、注入标记、API 次数、候选键与无服务/无清理标志。实际独立回读必须通过，不以本地 marker 或旧 completed=true 代替。

只读恢复的写请求即使在发送前被拒绝，也会记入审计并使测试失败；零对象 PUT 不能代替零表写入检查。若主机/磁盘损坏、文件被管理员替换，证据可能不完整；它不是独立删除日志、当前检查点权威或防回退机制。
