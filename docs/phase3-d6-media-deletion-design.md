# D6 照片删除设计

用户已批准 D6a–D6d 的默认值。本文定义首批后端的实现边界。整条回忆删除和文本擦除见 [单独的设计](phase3-d6-memory-deletion-design.md)，待评审。首批后端已实现，迁移为 `0035_media_deletion`，证据见文末“首批实现与验证”。未部署。

## 首批范围

首批处理 READY 照片的删除、撤销、到期清除，以及相册、回忆和待审批请求对删除状态的读取与写入约束。先用隔离数据库和模拟对象存储验收。整条回忆的删除请求、文本擦除、用户界面以及生产备份和恢复策略分别安排。取消尚未完成的上传继续走现有上传清扫流程。

## 生命周期

| 操作 | 条件与结果 |
|---|---|
| 删除 | 只允许上传者。同一媒体最多一个未撤销删除。记录数据库时间和 `purge_after = deleted_at + interval '168 hours'`。提交后停止直接读取和签发新链接。照片原有绑定保留。 |
| 撤销 | 只允许原删除者，须指明本次删除的 ID。拿锁后按数据库实时时钟判断，严格早于 `purge_after` 且无清除计划才可撤销。恢复原有授权和归属。撤销后再次删除会产生新一轮记录和新的截止时间。 |
| 清除 | 在截止时刻或之后，任务可提交一条不可变的清除计划。持久化计划与对象删除分开执行，任何重试都针对同一计划和同一组对象键。即使对象存储故障，照片保持隐藏，撤销也已关闭。 |
| 清除完成 | 只有全部目标对象删除成功或明确已不存在后才记录完成。生产备份最多再保留 30 天的承诺需要实际备份策略和恢复演练验证。 |

删除和撤销各自按调用者、操作和键做幂等分类。相同请求重放返回原操作事实，不刷新截止时间。不同请求复用原键返回冲突。撤销旧一轮删除的请求不得影响后来的删除。查不到照片或跨空间时统一按不存在处理。

## 并发与读取

- 删除、撤销和清除计划都用媒体锁 33018。用户写入先锁成员行，再取幂等键锁（编号实施前复核），最后取媒体锁。清扫任务只取媒体锁。回忆和相册保持现有的领域锁在前、排序后的媒体锁在后。
- 清扫候选只是提示。清除计划写入前须在锁内重查最新删除轮次、撤销记录和截止时间。普通的 `everything` 清扫继续拒绝已绑定或已预留照片。用户主动清除使用独立原因，只对同一轮已到期且未撤销的删除开放。
- 直接图片事实与内容接口必须检查删除状态，包括上传者。签发路径需明确读取和删除的先后次序，拿锁后读取状态并在锁内生成签名。签名计算本身无需访问对象存储。删除提交后才开始的请求一律拒绝。先完成授权的并发请求仍可能持有已签发链接，既有缓存或下载也无法召回。
- 相册有效照片、数量和封面候选排除删除中的照片。撤销后按原相册记录及封面规则重新计算。回忆历史保留原正文和位置，可用无可读地址的占位符表示删除照片。新增照片、直接编辑和提议审批在媒体锁后检查可用性，数据库守卫也应拒绝已删除照片。撤销不自动审批任何提议。
- 清扫沿用数据库计划提交后再调用对象存储的模式。枚举 staging 与所有 promotion attempt 键，并遵守现有迟到对象检查。若生产打开版本化或另有副本，须由 D5 策略覆盖这些副本。

## 恢复安全与发布门槛

真实照片发布前，需要独立于 PostgreSQL 的持久删除日志。单靠数据库 outbox 无法保证数据库整体丢失后仍知道尚未导出的删除。建议生产设计使用外部持久删除意图作为恢复屏障。无法确认的删除意图在恢复时按隐藏处理，等证据齐全再处理撤销。日志不可读或无法证明覆盖时，恢复环境保持关闭。日志存放位置、写入协议和恢复演练随 D5 单独评审。本批隔离实现只验证数据库生命周期和模拟清除。

## 验收清单

1. 上传者可删除伴侣回忆中的照片。伴侣和空间外账号不能删除、撤销或读取。已有绑定不释放给其他相册或回忆。
2. 删除后直接读取与签发均返回 404，模拟存储没有签名调用。相册封面回退，回忆全删后仍有正文，待审批请求不能用删除照片完成审批。
3. 复现媒体锁竞争的两种顺序。撤销先成功则任务不得清除。到期清除先提交则撤销失败。用可控时钟或数据库测试夹具覆盖截止点及前后，生产规则使用数据库时钟。
4. 清除前后模拟超时、部分键失败及对象已经不存在。验证原计划可重试、不会误删未删除媒体，只有全部确认后才记录完成。
5. 验证同键重放、改参冲突、多轮删除及旧轮次撤销。先做两种数据库角色的回滚预检，再在一次性库提交并运行全量回归。

| 情形 | 结果 |

| 删除提交后才开始的请求 | 404，不产生签名，上传者同样如此 |

### 偏离与新增决定

1. 设置相册封面现在先取 33021，再取照片的 33018。此前封面只取相册锁，既有用例 `P3-2a ... lock independence` 断言了这一点，已改为断言封面会等待媒体锁、移除不等待。代价是持有媒体锁的写入会短暂阻塞该相册的封面及其后的相册写入。锁序仍是单向的。
2. 清理任务改为读取三类候选后，用一条排序语句统一上锁，再逐类写计划。原来分类上锁，在“已删除照片和待清理照片同属一个写入请求”时可能与多照片写入形成环。计划语句仍在锁后重新判断。
3. 内容接口每次读取现在占用一个短事务并等待媒体锁。未做性能测量。
4. 守卫允许写入过去的 `deleted_at`，下限是 READY 时间和上次撤销时间。测试靠它安排截止时间，与既有媒体表做法一致。持有 `usapp_api` 权限的代码因此可以写入已到期的一轮，服务本身始终使用数据库当前时间。
5. CTest 新增目标 `media_deletion_db`，时限同为 30 秒，未调整任何 TIMEOUT。隔离脚本自身的总时限由 120 秒调整为 180 秒。

### 通知只描述确切的一轮

响应只说明它指明的那一轮。服务端的重放返回这一轮今天的事实，不说明照片现在是否可见，后来的一轮可能已再次删除它。两个写操作的响应也无法让客户端区分首次和重放。所以通知不再出现“已恢复”“仍然可用”，也不再对已到期或已清除的一轮提示可撤销。照片当前状态只来自随后的重新读取。

### 重试时错误能否证明原结果

服务端顺序（`MediaController.cc`，`MediaService.cc`）：过滤器 401/403 → 控制器 UUID 形状（404，146、164 行）→ 请求键格式（400）→ 成员行（`SPACE_NOT_FOUND`，747 行）→ 33025 → 按键分类（重放或 `IDEMPOTENCY_KEY_REUSED`，751–758 行）→ 33018 → 状态检查。

判断标准有两条，都满足才结束操作：错误发生在重放检查之后，所以这个键当时没有提交；拒绝依据的状态不会再变，所以仍在路上的同键请求也不会提交。

| 操作和错误 | 产生位置 | 早于重放检查 | 状态能否再变 | 能否证明原结果 | 处理 |
|---|---|---|---|---|---|
| 撤销 `MEDIA_UNDO_CLOSED` | 819 行预检，838 行守卫 | 否 | 不能：时间只前进，计划不可删除 | 能 | 结束 |
| 撤销 `MEDIA_DELETION_NOT_ACTIVE` | 815 行 | 否 | 不能：一轮只有一条撤销记录 | 能，这一轮已被其他请求撤销 | 结束 |
| 撤销 `MEDIA_NOT_FOUND`（状态） | 811 行 | 否 | 不能：轮次和删除者不可变 | 能 | 结束 |
| 撤销 `MEDIA_NOT_FOUND`（UUID 形状） | 控制器 164 行 | **是** | 不适用：同一输入总被同样拒绝，原请求也到不了服务 | 能 | 结束。界面的 ID 都来自服务器，实际到不了这里 |
| 删除 `MEDIA_NOT_FOUND`（状态） | 778、787 行 | 否 | 不能：归属和清除计划不可变。未 READY 的照片理论上可变，但界面只对 READY 照片提供删除 | 能 | 结束 |
| 删除 `MEDIA_NOT_FOUND`（UUID 形状） | 控制器 146 行 | **是** | 同上 | 能 | 结束 |
| 删除 `MEDIA_ALREADY_DELETED` | 783 行 | 否 | **能：撤销后照片可以再次删除** | **不能**。仍在路上的原请求可能之后提交 | 结束重试，不判断原结果（见下文“删除重试的收尾”） |
| `SPACE_NOT_FOUND`、400、401、403、429 | 重放之前或之外 | 是 | — | 不能 | 保留 |
| `IDEMPOTENCY_KEY_REUSED` | 分类时 | 否 | — | 不能证明这次请求的结果 | 保留 |

`MEDIA_ALREADY_DELETED` 不能证明原结果，它的处理见下文“删除重试的收尾”。

### 删除重试的收尾

取代这一节早先“保留键和请求”的做法。那样会留下一个可能永远没有结论的提示，而且照片被撤销后，点旧的重试按钮会再次删除它。

未确认的删除在重试时收到 `MEDIA_ALREADY_DELETED`：刷新相关页面，结束这次重试，提示“这张照片目前是删除状态”和“之前那次删除请求的结果无法确认”，不说原请求成功或失败。照片之后重新可见时，再次删除要重新确认，并使用新的键。其他重试规则和只描述确切一轮的通知不变。

已知的剩余情况：这个错误不能排除原请求仍在路上。如果它在其他设备撤销之后才到达服务器，仍可能产生一轮新的删除。客户端已不再跟踪这个键，用户会在页面和“最近删除的照片”里看到结果，并可以撤销。
