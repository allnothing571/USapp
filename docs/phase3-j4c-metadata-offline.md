## 1. 文件与行为

- `tools/j4c_metadata.py`：实现发布模型的 Metadata 接口；客户端仍默认禁止网络。没有初始化、资源创建、凭据加载或在线启动入口。
- `tools/j4c_tablestore_sdk.py`：增加带旧值条件的 operation 索引更新，仅允许 intent 到 committed/aborted，保留操作绑定；原批次及周期行依旧只插入。
- `tests/test_j4c_metadata.py`：14 项离线测试，客户端明确为假实现，不将其事务行为当作供应商保证。
- `tests/test_j4c_tablestore_sdk.py`：新增 3 项真实 SDK 编解码测试，内存响应桩运行于连接和域名解析禁止条件下。

表行 payload 为规范编码。分区固定 journal_id；行类型为 head、batch、operation、cycle。head/current 必须已存在且有效；**缺失检查点绝不推断为空日志**。初始化及所有权核验仍须另做，不自动登记旧数据。

批次索引 ID 为 20 位十进制序号，值只含对象键；operation 索引保存不可变绑定与阶段；cycle 索引 ID 是周期三元组规范编码的 SHA-256（Secure Hash Algorithm 256-bit，256 位安全散列算法），值保存完整三元组以检测不匹配。

## 2. 提交顺序与结果未知

1. 读取元数据，结束读事务，然后在事务外读取并验证整个已提交对象链和所有索引。
2. 在事务外读取候选对象，检查对象键、完整规范字节、双层链、周期及操作绑定、后继检查点。
3. 开始写事务，重读并比较完整旧检查点；变化则返回 HEAD_CHANGED。
4. 插入批次，插入操作或条件更新其阶段，插入新周期，条件推进检查点。
5. 同一事务提交这些元数据。发送提交前移除本地待回滚句柄：回执丢失或校验失败返回 UNKNOWN，**不自动回滚，也不盲目重发提交**。后续重新读取规范链判断结果。

对象存储调用全部位于元数据事务之外；事务内只执行该元数据存储自己的读写调用。写入阶段报错可尽力中止事务；提交阶段报错并不能证明未生效。中止失败也不被报告为成功。

不假设本地事务具有可重复读：用完整检查点包围分页索引读取，前后不一致则拒绝。此方法依赖唯一合法写协议的单调检查点及原子索引提交；拥有原始写权限的其他主体篡改索引或回滚检查点，仍是独立权限及防回退门槛。

## 3. 有界与失败关闭

分页每页最多 100 行，跨类型总上限 4096 行、8 MiB 载荷，单行载荷上限 64 KiB，已提交批次最多 1024。连续键必须同分区、同类型并严格前进；拒绝重复行、部分行令牌、异域连续键、批次缺口及非规范载荷。发布模型既有每对象 1 MiB、完整快照 8 MiB 和重试轮数上限保留。这些是原型限制，不是已测得的云端容量指标。

同一适配器实例串行使用单个客户端；这不是跨进程互斥。跨实例竞争依赖事务内的旧检查点条件；实际冲突、隔离和持久性须实测。没有新增整体网络调用时限；J4c1 子进程看门狗仅约束测试进程，不能冒充实际单次操作时限。真实连接、慢响应、证书和持久提交仍待验证。
