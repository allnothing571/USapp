## 1. 本批已实现的内容

新工具 `tools/deletion_journal_batches.py` 为 J4a 版本 2 批次封装的只读校验器。它逐批检查操作身份、完整目标清单、请求指纹和整批确认，再调用未修改的 J1 校验器检查逻辑事件链及删除/撤销/清除语义。输出始终 `serving_allowed: false`、`status: replay_required`。

它不提供在线写入器、可信检查点来源、云适配器、权限策略部署、旧数据登记或数据库恢复。封装完整不代表生产存储已经原子发布，更无法发现生产者起初就漏报的级联照片。

## 2. 要解决的故障范围

- 应用 PostgreSQL 或宿主机丢失、恢复旧备份时，删除事实及检查点不随数据库一起回退。
- API 进程超时、丢失回执、多实例同时写日志时，重试不能重复登记或改变已经绑定的操作。
- 截断的日志、缺失的批次、部分级联确认和过旧检查点均不得成为恢复授权。
- 不声称同一云账号完全失陷后仍安全，也不声称同地域同时不可用时能够恢复服务。跨账号/跨地域灾备仍需 D5 的选择与演练。
- UUID（Universally Unique Identifier，通用唯一标识符）和摘要也是隐私相关元数据，不公开、不当作匿名数据，不写入用户正文、原始对象键或凭据。

## 3. 资源方案比较与推荐

| 方案 | 构成 | 收益 | 代价及限制 |
|---|---|---|---|
| A，已选设计方向 | 专用 OSS（Object Storage Service，对象存储服务）日志桶；独立 TableStore 实例保存权威头、操作索引和已登记轮次；应用外的日志服务与检查点服务身份 | 不依赖应用数据库/磁盘；托管事务可覆盖头和索引；日志正文可单独保留 | 新云产品、网络调用、客户端依赖、权限和费用均需核实；不是只加一个 Bucket 就完成 |
| B | 独立主机上的单写日志服务、独立事务存储及异地不可变副本/检查点见证 | 更容易使用现有标准库做原型；不必采用 TableStore | 主机、磁盘同步、故障切换、防回退和备份自行维护；不能放回应用主机，也不能把本地文件叫作独立见证 |

**A 的选择不等于云资源或生产配置授权。** 测试地域已选上海，其余资源名、账号归属、服务位置和预算尚未确定。已查基础测试费率，未核定生产月费，也没有月费承诺。本批没有引入任何客户端依赖。真实客户端需单独评估已有库或厂商 SDK（Software Development Kit，软件开发工具包），不能默认现有 C++ 图片适配器已经支持 TableStore。

### 3.1 A 的职责划分

1. **日志桶**：只保存不可变、完整的批次对象。对象键建议为 `journals/<journal_id>/batches/<batch_hash>.json`。不能复用上传图片的测试桶或生产媒体桶。
2. **权威检查点**：TableStore 中显式保存版本、日志身份、批次序号/摘要、逻辑事件序号/摘要。它来自可信在线检查点服务，不能由待验证快照临时重算。
3. **操作索引与轮次索引**：同一 `journal_id` 分区内保存操作完整绑定和终态，以及删除轮次是否已登记。头和这些索引在一个事务中提交；不能只更新头再异步补幂等索引。
4. **检查点服务**：验证候选批次及其前驱，执行受限的头推进，禁止调用方任意指定旧头。生产 API 不持有直接修改检查点、删除日志或管理保留策略的凭据。
5. **恢复读取者**：从独立可信部署清单固定日志身份和恢复实例；实时读取权威检查点，读取其引用的确切日志链。不能按对象列表顺序、文件时间或“最大看起来像序号的文件名”挑头。

这里的独立首先指不依赖应用数据库的备份、凭据和恢复流程。若桶、TableStore 和管理身份仍在同一账号，账号最高权限是共同故障域，必须明确承认，不能用“两个云产品”宣称消除了该风险。

## 4. 建议的发布协议，尚未实现

1. 读取当前已提交头以及相同操作 ID 的索引。相同操作和载荷重试返回原状态；不同载荷拒绝。未知结果不能换新操作身份猜测成功。
2. 为整个已冻结操作生成一个不可变批次，包含所有目标及连续逻辑事件。生成摘要并上传完整对象；已存在时须比较实际完整字节，不能只凭对象名或 ETag 推断相等。
3. 在上传与独立读取核对完成后，开始同一日志分区的短事务。**不跨应用数据库事务等待外部网络，也不在这个短事务里上传对象。**
4. 事务重新检查前驱头、操作绑定、轮次登记状态，然后原子推进头并写入操作/轮次索引。这里需要 CAS（Compare-And-Swap，比较并交换）式前驱核对，不能用覆盖写实现竞争。
5. 前驱已改变则候选对象不是已发布日志，不能触发业务效果；重新读取当前状态后，仍按同一操作身份分类。未引用对象只算孤儿候选，不能从列表中自动纳入恢复链。其清理须另有受控协议，不能让日志发布者获得任意删除权。
6. 只有对象完整性和权威头/索引提交都得到确认，才给 J2 返回 Ready。上传成功但头未提交、事务提交回执丢失、服务不可用都不能视为 Ready。
7. 最终 committed/aborted 同样是一个覆盖整个操作的新批次。相同终态重试只核对；矛盾终态或变更清单拒绝。超时不证明 aborted。
8. 对操作大小、目标数量、事务字节和时限设置明确上线限额；超限必须在业务效果前拒绝，不允许将一个级联操作静默拆成多个可部分成功的操作。

**已核实的厂商约束**：TableStore 本地事务可原子读写多行，但写入限同一分区键，事务最长 60 秒且写入量有限。表创建时需启用该功能。此处采用一个日志身份作为分区的建议，仍需真实并发、回执丢失和一致性验证。[官方本地事务文档](https://www.alibabacloud.com/help/en/tablestore/table-store-service/local-transactions)

尚未证明：目标地域/实例和客户端支持情况，实际普通读的一致性及最新检查点获取路径、恢复元数据防回退、多实例故障窗口、调用上限、配额及费用。不能把上述厂商事务能力等同于已经完成整个协议。

## 5. J4a 的版本 2 格式

每行是一个完整批次对象；对象必须包含：

| 字段 | 含义 |
|---|---|
| version=2、journal_id | 格式版本、日志部署身份 |
| batch_seq、batch_id、previous、hash | 连续批次序号、唯一批次身份、上一批摘要、本批摘要 |
| operation_id、action、phase、request_fingerprint | J2 的稳定操作身份、动作、阶段、不可变请求指纹 |
| subjects | 排序且非空的完整目标清单，保留 target_kind、target_id、cycle_id、intent_id |
| events | 与清单逐项对应的完整 J1 事件；没有额外目标，也没有缺少目标 |

目标顺序与 C++ 协议一致：memory 在 media 之前，然后按目标、轮次和意图身份排序；同一操作不允许重复目标或意图。指纹允许空字符串以匹配现有 J2 兼容语义，但空与非空不是同一个载荷，不能在重试时改变。

批次摘要沿用 SHA-256（Secure Hash Algorithm 256-bit，256 位安全散列算法）及 J1 规范 JSON 编码，不包括本对象的 hash 字段。批次检查点恰好包含 `version=2, journal_id, batch_seq, batch_head, event_seq, event_head` 六个字段，须来自独立可信来源。工具同时验证外层完整批次链与内层 J1 逻辑事件链。

同一个操作只能有一个 intent 和至多一个整批终态；终态必须匹配原动作、指纹及全部目标身份。字段未知、重复 JSON 键、非法数字、截断、重复操作、部分批次、清单重排或变更、错误逻辑事件、未知删除轮次、不同日志或检查点不匹配都拒绝。cleanup 仍只允许媒体。

新格式没有自动转换或覆盖旧日志。版本 1 仍由旧工具验证；生产不能在同一身份下把已有历史偷偷改写成版本 2。是否需要显式格式切换边界，取决于启用前是否确实没有历史。

```powershell
python -B tools/deletion_journal_batches.py --journal <closed-batches.jsonl> --checkpoint <independent-latest-head.json> --expected-journal-id <uuid> --output <new-report.json>
```

成功仅输出 `JOURNAL_BATCH_VALIDATED_REPLAY_STILL_REQUIRED`。报告版本为 2，包含已校验批次头和未决操作；仍固定不允许服务。失败退出 2、固定错误标签，不回显输入内容或路径；不覆盖已有输出。

## 6. 凭据、保留、配额和成本

- RAM（Resource Access Management，资源访问管理）至少区分：API 到日志服务的调用身份、批次对象发布身份、检查点推进身份、恢复只读身份、资源管理身份。管理身份和云主账号密钥不进入应用；最终权限策略必须在具体产品/地域确定后核对实际操作名与资源范围，当前不生成未经验证的策略 JSON。
- 日志服务与检查点服务的凭据不沿用媒体上传者、媒体删除者或原始图片读取者的凭据。日志只记录稳定身份与摘要；HTTP/错误日志不记录正文、对象内容或认证材料。
- 真实测试使用新资源、新身份和合成数据。凭据由用户保存在仓库外，只按字段名传入，不能把真实密钥写进命令参数、报告、镜像或保留容器的环境。
- 建议生产日志对象使用 WORM（Write Once Read Many，单次写入多次读取）保留；锁定后不能缩短期限或提前删除，这是需要单独批准的不可逆配置。对象桶保持与可变检查点分离，不能把需要更新的 head 文件放进锁定桶。[官方保留策略文档](https://www.alibabacloud.com/help/en/oss/user-guide/oss-retention-policies)
- 建议不为日志链和检查点配置自动删除。照片/文字备份的“清除后最多 30 天”不等于删除日志可以保存 30 天后丢弃：从创世记录验证的链仍依赖旧前缀。压缩或裁剪需要独立可信基线与恢复证明，另批处理。
- 生产保留锁的天数、账号与地域隔离、元数据长期保留和灾备副本仍待用户确认；本批没有锁定任何保留策略。
- 成本按批次数、目标数、读写请求、重试/孤儿候选、检查点事务、存储期限和恢复扫描计算。通常 intent 与最终确认各需一个批次，不能只算一条删除记录。暂无价格或月费估算；预算提醒不能被当成强制止付。预算和报警对象确定前不创建资源。
- 网络调用必须有单次/整次操作时限；单日志分区串行推进会影响吞吐。配额或服务不可用时拒绝产生效果，而不是退回本地未受保护模式。

## 7. 旧数据与启用边界

推荐先选择**严格空基线启用**：在维护窗口停止业务写入和相关调度，核对新功能数据确实为空，再建立新的日志身份与零检查点，最后由尚未完成的 J3 开放协议决定是否可启动。不能根据旧对话中生产停留在 0024 的记录，直接认定今天仍为空。

空基线至少核对媒体、回忆、删除/撤销、回忆级联链接、清理计划/扫描、迟到对象和文字擦除记录；任何非空结果都停止此流程。清单必须与届时实际表和写入路径逐项核对，不能只统计未撤销删除轮次。

如果已有数据：另做有来源和截止边界的基线登记协议，覆盖历史删除、撤销、级联、清理、清除及确切恢复语义。不允许伪造“刚刚写入、发生于效果之前”的历史 intent，不从当前对象不存在推断历史删除成功，也不因当前未删除就排除历史轮次。J4a 版本 2 仍拒绝未知轮次 purge，**没有实现或允许旧数据登记**。J2c2 对未登记旧 user_deleted 计划的拒绝继续保留。

## 11. J4b 同步发布原型与假适配器（2026-11-07）

### 11.1 本批实现

`tools/deletion_journal_publication.py` 是注入式、同步、仅供离线验证的参考实现。`Objects` 和 `Metadata` 是抽象契约，不包含 OSS/TableStore 客户端；内存假适配器只在 `tests/test_deletion_journal_publication.py` 中。本原型不连接网络、不读写文件或凭据、不操作业务数据库，没有接到 C++ Journal 接口、HTTP 服务、main 或部署配置。

操作身份、动作、指纹及完整目标先复制和规范化，避免调用方修改原对象改变已准备载荷。每次从假元数据原子读取完整检查点、规范对象键和操作/轮次索引，读取确切不可变对象，通过真实 J4a/J1 校验链，并从链重建索引对照。缺失对象、错误检查点或半份索引均不得回退到缓存或扫描桶补出一个“最新头”。

候选批次身份由操作、阶段和前驱摘要稳定派生；相同前驱重试产生相同字节和键。写入候选之后再次读回完整字节，才允许元数据提交。元数据契约须独立检查候选，随后在同一日志分区内比较完整前驱并原子写入头、所有操作索引、轮次索引及引用。假实现用同一进程锁保护一个完整状态替换；**这不是 TableStore 事务能力的真实验证**。对象读写带有测试断言，不能在假元数据事务锁内进行。

若前驱竞争失败，原型有界重新读头、仍按原操作身份分类。已提交的相同操作直接返回原状态；不同载荷冲突。竞争失败的候选对象保留为未引用孤儿，不参与检查点引用链，不自动清理或采纳。未知提交、异常、权限类失败、损坏数据不转换成 aborted。

返回 `Ready` 只表示日志 intent 接受，不表示业务删除已提交，更不表示允许服务。业务效果确认仍由 J2 承担；本模型只接受已有确定分类的终态请求，未实现数据库效果证明或网络客户端授权。离线 `inspect` 报告继续固定 `serving_allowed: false`。

### 11.2 原型界限，不能作为生产承诺

- 为审查完整性，本原型每次读取整条受检查点引用的链，并核对完整索引；这不是生产吞吐或索引读取方案。真实实现仍需经过证明的有界索引/分段读取设计，不能直接把同步整链读取放入 Drogon 事件循环。
- 默认原型保护参数：最多 3 轮竞争重读、1024 批次历史、每操作 256 个目标、每对象 1 MiB、每快照 8 MiB。均可由测试构造参数控制，**不是已批准的生产配额**。达到上限即拒绝，不截断历史、不拆分级联、不自动开启新日志身份。
- 此处只限制工作量/调用次数，不提供真实墙钟超时。真实网络适配器的单次与整次时限尚未实现；没有证明任何 SDK 的重试或取消行为。
- 假元数据声明 read 为当前可信原子快照。本原型能阻止陈旧读对应的候选覆盖仍然更新的权威前驱；**不能识别整个权威服务被一致回滚后仍声称“最新”的旧状态**。这一风险仍需独立可信检查点服务、不可与应用库一起恢复的状态及真实反回退流程解决，哈希链本身不解决。
- 没有验证真实持久性、进程重启、断电、分区事务、云权限、不可变保留、读取一致性、配额、费用、身份认证或部署隔离；没有启动/恢复屏障。没有旧数据登记或孤儿候选清理权限。
