## 1. 最小费用与预算建议

不购买服务器、资源包或预留计算。候选配置为 TableStore 的 CU（Capacity Unit，容量单位）按量模式、高性能实例、预留读/写均为 0，以及 OSS（Object Storage Service，对象存储服务）标准本地冗余存储。不是 VCU 预留计算；创建界面如出现预付费、非零预留吞吐或不兼容事务，先停止，不自动改规格。

2026-11-07 官方中国内地价格页列出的高性能按量费率为：读 0.01 元/万 CU，写 0.02 元/万 CU，存储 0.0015 元/GB/小时，外网下行 0.8 元/GB。低流量测试应使用按量，而不是为了本次测试购买资源包。[官方价格](https://www.aliyun.com/price/detail/ots)

**估算情景，不是报价、最低扣款或硬性封顶：**

| 假设用量 | TableStore 估算 |
|---|---:|
| 读 10 万 CU、写 10 万 CU | 0.30 元 |
| 10 MiB 数据保留 24 小时 | 约 0.00036 元 |
| 外网下行 0.1 GB | 0.08 元 |

以上合计约 0.38 元，另加少量 OSS 存储、请求和外网流量。因此我对当天完成的小规模基础测试的判断是**几角至 1 元量级**；建议本轮留 **5 元预算**应对重跑。费用以账号实际价格、控制台和账单为准，不将试用额度或账号折扣计入保证。大规模并发、长时间轮询、重复扫描、实际不可变保留测试及后续生产费用不在这个估算中。

CU 不是请求次数；数据大小和事务操作也影响用量。预留吞吐不为 0 时，无请求也收费；官方允许将两项预留值设为 0。[预留吞吐说明](https://help.aliyun.com/zh/tablestore/product-overview/what-is-reserved-read-or-write-throughput)

CU 模式目前不能在产品层封顶整体资源使用，所以 5 元只能是本轮人工预算/停止阈值，不能承诺精确在 5 元自动停账。需要脚本的调用、数据量和运行时长限制，加上账单核对；不能把预算提醒等同于止付。[计费模式说明](https://help.aliyun.com/zh/tablestore/table-store-service/product-overview/billing-overview/)

**避免闲置收费：真实客户端及本地故障测试准备好之前，不创建收费表。** 不会为了估算而先开资源。

## 2. 候选测试资源（名字尚未占用或创建）

`<RUN8>` 为一次性 8 位小写随机后缀，最终名称还须在创建前核对；不能去寻找或复用名字相近的现有资源。

| 项目 | 建议配置 | 状态/限制 |
|---|---|---|
| 账号 | 用户现有云账号下的新独立测试资源 | 同账号不是最高权限隔离；不改变现有媒体资源 |
| 地域 | 上海 `cn-shanghai` | 用户已同意；不是跨地域灾备决策 |
| 日志桶 | `usapp-j4c-log-<RUN8>` | 私有、阻止公共访问、标准、本地冗余、版本控制关闭、默认 OSS 托管加密 |
| 额外桶能力 | 不配置生命周期、跨地域复制、加速、网站托管或跨域 | 没有浏览器直传；不放媒体数据 |
| 保留锁 | 基础接口测试不创建或锁定保留策略 | 因此基础通过不能宣称防篡改；真正锁定测试另获授权 |
| TableStore 实例 | `uj4c<RUN8>`，CU 模式、高性能规格 | 最终界面必须支持本次局部事务；不选择预留计算或资源包 |
| 数据表 | `journal`，宽表模型 | 创建时开启局部事务；不使用主键自增 |
| 主键 | `journal_id` STRING、`row_type` STRING、`row_id` STRING | 第一列为分区键；同日志全部事务写入同一分区 |
| 表属性 | `time_to_live=-1`、`max_versions=1`、`allow_update=true`、预留读/写 0/0 | SDK 预检编码/解码已做桩验证；真实资源仍须核对，不能凭默认值继续 |
| 额外功能 | 不创建二级/多元索引、通道、数据湖投递、全局表或额外备份产品 | 降低费用与权限面；这不是生产备份方案 |
| 数据 | 随机日志身份、合成目标和故障用例 | 无真实照片、正文、会话或生产 ID |

`row_type` 中的 head、batch、operation、cycle 是同一物理表里的逻辑行，不是另外创建云端索引服务。操作与轮次索引和 head 仍须同一局部事务提交。

上海是官方支持的地域，但客户端应使用**该实例控制台给出的数据服务地址**；不能把地域级管理接口地址误用为实例数据地址。[实例与 Endpoint 概念](https://help.aliyun.com/zh/tablestore/table-store-service/product-overview/basic-concepts)

官方要求建表时开启局部事务；遗漏后再开启可能需要工单，不应通过测试期间随意改表来绕过。[创建局部事务](https://help.aliyun.com/zh/tablestore/table-store-service/developer-reference/startlocaltransaction)

## 3. 权限模板：仅候选，不直接应用

模板位于 `docs/examples/j4c/`，所有尖括号占位符都未替换；不能直接绑定，更不能先换成全资源通配符试通。每个运行身份都应是新建、无其它权限/组继承、无控制台访问的测试身份。

| 身份 | 模板 | 允许范围 |
|---|---|---|
| 批次发布者 | `object-publisher.policy.json` | 仅本日志批次前缀的 PutObject/GetObject，无表写权限 |
| 检查点事务写入者 | `checkpoint-writer.policy.json` | 仅读取本日志批次；仅本表描述、行读写及局部事务；无对象写/删除权 |
| 恢复数据读取者 | `recovery-reader.policy.json` | 本日志批次读取、本表描述/行读取及 StartLocalTransaction/AbortTransaction；无数据写入或 CommitTransaction 权限，事务控制仍可能计费 |
| 资源设置与清理 | 用户单独控制的管理身份 | 不提供给应用和测试运行器；仅在具体步骤、范围得到批准后使用 |

TableStore 操作名称和表级资源语法已按官方文档核对。模板是表级边界，未设计或验证按行分区隔离；测试表不承载其它日志或真实数据。[官方授权语法与操作资源表](https://help.aliyun.com/zh/tablestore/table-store-service/authorization-policy-syntax-and-elements)

模板不允许 ListObjects、DeleteObject、DeleteRow、BatchWriteRow、Create/Update/DeleteTable、管理实例、修改权限/生命周期/保留策略等操作。若最终客户端确实需要新增操作，先解释用途并修改模板审查，不绑定 `oss:*` 或 `ots:*`。

**重要权限边界：** PutRow/UpdateRow 权限本身不能保证检查点只向前推进，也不能证明索引不可变。检查点服务必须校验前驱与完整操作；该身份的密钥不能进入业务 API 或批次发布者。无保留锁的 PutObject 也不能证明不可覆盖：基础测试必须核对字节和客户端禁止覆盖行为，云侧不可变性仍未验证。

模板只是 Allow 白名单，并不抵消其它已有授权；因此还要核对无组/角色/系统策略的额外权限，并实际做允许与拒绝测试。不能仅凭 JSON 可解析就宣布最小权限通过。

## 4. 分阶段实际步骤

1. SDK 版本/隔离依赖及受限客户端离线验证已完成第一批（J4c1）；真实 HTTPS、完整 OSS/TableStore 发布适配器、凭据文件/实时运行器、网络整次截止仍未完成。不能直接用同步内存模型或 SDK 响应桩冒充云客户端验收。
2. 路线、上海地域及本轮 5 元预算已确认；仍须确定测试窗口、最终资源名和清理范围，再取得真实创建授权。预算确认不等于创建、锁定保留或自动清理授权。
3. 用户创建新测试资源，逐项核对计费、表主键、事务开启、读写预留 0/0 和无自动过期。若条件不符停止。
4. 确认实际资源后生成精确权限，按角色分别绑定。密钥只保存在仓库外的用户文件，不发送到聊天、不放命令参数或容器环境中；运行器只读挂载已批准文件。
5. 先以描述接口核对账号/地域/实例/表/桶/日志身份白名单；再做合成行和对象测试。不探测旧部署或共享数据库。
6. 每项测试保存完整退出状态和脱敏结果，失败即停止该阶段。发生未知提交按相同操作分类，不写 aborted 猜测回滚。
7. 导出确切对象键和行主键清单，核对全部只属于本次资源。清理身份、删除时机与是否移除测试表/实例/角色在执行前另行确认，不清理既有资源。若未清理数据，存储仍可能继续计费。

### 基础接口验收矩阵

| 项目 | 正向 | 负向 |
|---|---|---|
| 身份与资源 | 只访问清单中的新资源 | 其它前缀/表与危险动作拒绝；不读取其它数据来证明拒绝 |
| 对象完整字节 | 上传后完整读回，核对批次链 | 同键不同字节冲突；截断、损坏和错误桶拒绝 |
| 单分区事务 | 头和操作/轮次索引全部提交 | 中途丢弃、提交回执丢失、跨分区写和错误事务拒绝/核对 |
| 并发 | 相同操作一次提交，不同操作合法串行 | 同 ID 不同载荷拒绝；旧前驱不能覆盖当前头 |
| 检查点 | 由权威服务读取当前头并验证确切引用链 | 缺行、分叉、缺对象或旧候选不补造最新头 |
| 用量与时限 | 限定调用和合成数据规模，按实际消耗记录 | 超时/错误/额度耗尽不允许业务效果，不无限重试 |

事务、请求时限、每次测试最大调用/字节数尚须写入真实运行器；表格不是已实现的自动限制。基础测试不包含锁定保留、防整个权威元数据一致回退、备份恢复或生产启用，不能关闭这些门槛。
